### 目标：基于 MuMu 模拟器屏幕视觉感知，构建超过职业选手水平的钟馗 AI（先单英雄，后扩展）

### 0.2 与目标之间的核心差距（诚实评估）

1. **决策不是 AI**：当前 Agent 是手写规则（最近敌人→移动→放技能），上限约等于"会玩但很菜"。无任何学习型策略。
2. **感知不完整**：只有 4 类检测框，没有：小地图（全局视野）、血条/冷却/金币/等级、敌我阵营、单位追踪 ID、视野外预测。这是从"屏幕"走向"游戏状态"的关键缺口。
3. **没有学习数据闭环**：比赛录像 → 状态+动作 → 训练集 → 策略模型 这条流水线只有零散脚本，未打通、未验证质量。
4. **没有评测体系**：无法回答"AI 现在什么水平"。
5. **工程问题**：每次动作都 `subprocess.run('adb')`（延迟 30-100ms 且不可控）；代码重复（5 份 ScreenCapture）；无统一状态 schema；无日志/监控；无多实例管理。
6. **算力受限**：8GB 本机 GPU 只够小模型训练与推理；"超过职业选手"的最后冲刺（大规模自博弈）需要云 GPU，计划按"本机可达 + 云 GPU 冲刺"两档设计。

### 0.3 可行性依据（业界参照）

- **[绝悟（JueWu）](https://mlanthology.org/neurips/2020/ye2020neurips-playing/)：腾讯王者荣耀 AI**，先监督学习（模仿），后自博弈强化学习，5v5 击败职业选手（[AAAI 2020 单挑版](https://mlanthology.org/aaai/2020/ye2020aaai-mastering/)）。它拿到的是**游戏内部状态**——我们的难点正在于要从屏幕像素重建同等级的状态。
- **[AlphaStar](https://deepmind.google/blog/alphastar-grandmaster-level-in-starcraft-ii-using-multi-agent-reinforcement-learning/)（Nature 2019）**：星际争霸 II，**纯屏幕像素（主镜头 + 小地图）+ 模仿学习 + 大规模自博弈**达到宗师级，击败职业选手。这是"屏幕视觉 → 超人类水平"已被证明的最强先例，也是本计划技术路线的直接依据。
- 社区参考：KataCR（皇室战争非嵌入 RL+CV）等证明小游戏屏幕方案可行；王者荣耀"农活"外挂证明屏幕操控工程可行（也提醒封号风险）。

**结论：路线可行，但必须承认——纯像素打 MOBA 到职业水平，公开文献中尚无先例，感知质量是最大瓶颈，自博弈算力是第二大瓶颈。计划按里程碑推进，每步都有独立交付价值。**

```

└───────────────┬──────────────────────────────────────────────────────────┘
                ▼
┌────────────────────────── 感知层（目标：<50ms） ──────────────────────────┐
│ ① 主战场检测：YOLO11s TensorRT（11 类） + ByteTrack 追踪（稳定 ID/速度）   │
│ ② 小地图：固定 ROI + 圆点聚类 → 全局坐标（敌我+野怪+兵线+塔，含视野外）    │

                ▼
┌──────────────────────── 状态表示 GameState（定版 schema） ────────────────┐

└───────────────┬──────────────────────────────────────────────────────────┘
                ▼
┌────────────────────────── 决策层（目标：<50ms） ──────────────────────────┐
│ 分层策略：                                                               │
│   L0 宏观（策略节奏）：推塔/开团/撤退/清线/支援/打野 → 目标选择（每次决策）│
│   L1 微观（战斗操作）：移动方向(连续角)、技能释放(点按/拖瞄/取消)、攻击键   │

                ▼
┌────────────────────────── 动作层（目标：<20ms） ──────────────────────────┐

│  / buy_item / recall / summoner / active_item / camera                    │
│ 执行器：mumu-python-api(TCP 常驻) 优先，adb 兜底；轨迹合成（贝塞尔平滑）   │

└───────────────┬──────────────────────────────────────────────────────────┘
                ▼
┌──────────── 数据飞轮（离线，与在线 Agent 共用同一套 schema） ─────────────┐
│ 录像源(比赛录像/自录) → 状态提取 → 动作反推(多通道+交叉验证+人工校正)       │
│ → (state_seq, action) 训练样本 → BC 训练 → 在线 Agent → 新录像 → RL 自博弈 │
└───────────────────────────────────────────────────────────────────────────┘
┌──────────── 评测体系（每里程碑必跑） ─────────────────────────────────────┐
│ 人机(难度1-5)胜率 → 真人低段位胜率 → 段位爬升速度 → 录像回放对比(价值评分)  │
└───────────────────────────────────────────────────────────────────────────┘
```

## 2. 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 策略形态 | 感知-决策分离（结构化状态 + 小策略网络），**不是**端到端 VLM 大模型 | 8GB 算力、<50ms 延迟、数据量小；VLM 只做离线辅助（动作反推、复盘评分） |
| 检测模型 | YOLO11s（或 n），TensorRT FP16 导出，960×540 输入 | 8GB 显存下 15-20 FPS；当前 yolov8n 可直接迁移继续用 |
| 追踪 | ByteTrack（ultralytics 内置 botsort/自定义轻量 IoU+运动模型） | 单位 ID 稳定 → 速度/朝向估计 → 预判与连招前提 |
| 全局视野 | 小地图圆点检测 + 单应变换（标定 2-3 组点）映射全局坐标 | 弥补主镜头视野不足，是"宏观决策"的数据基础，成本低收益极高 |
| 动作反推 | 多通道并行 + 交叉验证 + 人工校正标注器 | 录像无原始输入，单一通道不可靠（你已踩过：箭头/位移/按钮三套各有缺陷） |
| 策略网络 | 小 Transformer（输入=结构化 GameState 序列，输出=动作分布），先 BC 后 PPO | 与 绝悟/AlphaStar 同路线；结构化输入在小样本下远优于像素端到端 |
| 自博弈 | 先 1v1 墨家机关道（双开即可），再 5v5 峡谷（4-5 开 + 云 GPU 可选） | 迭代速度快 10 倍，先验证 RL 闭环 |
| 英雄范围 | 钟馗单英雄闭环 → 数据/模型按英雄参数化（hero_id 进特征） | 你已确认 |

## 3. 里程碑（M0→M6，含验收标准）

> 单人 + 本机 4060 的乐观时间估计。每个里程碑结束必须跑通验收项，才进入下一个。

### M0 工程基座（1-2 周）—— 把散装脚本变成流水线
**交付物**
- 包结构重构（见 §5 目录树）：`capture / vision / state / action / policy / train / eval / utils`，消灭 5 份重复 ScreenCapture。
- 统一 GameState schema（JSONL，字段定版，见 §4.2）；统一配置文件（yaml）；日志 + 每局存档（画面录像 + 动作事件流）。
- 延迟基准脚本 `bench_latency.py`：量化 mss 抓帧、adb、mumu-python-api、scrcpy 四路延迟，选出采集+执行主通道。
- 对局状态机 `MatchStateMachine`（`wzry/state/match_state.py`）：WAITING（局外等待）→ IN_MATCH（对局内）→ POST_MATCH（结算），基于小地图暗圆 + 阵营色点启发式识别，带滞回防抖；配合 `scripts/m0_agent_loop.py` 被动值守（默认不注入任何输入，只观测+记录）。
- 多实例管理 `mumu_farm.py`：**当前阶段单实例即可**；3-5 开为后期扩充（MuMuManager 启停/分配实例、独立 ADB 端口、一键开进对局）。
- git 仓库 + 数据目录规范（raw_videos / states / actions / datasets / runs 分层）。

**验收**：单实例端到端（抓帧→检测→决策→动作）延迟 ≤200ms 且可复现；3 开实例同时运行互不干扰；任一脚本 `--config` 启动。

### M1 感知系统（3-4 周）—— 从"几个框"到"游戏状态"
**交付物**
1. **11 类检测 + 追踪**：数据集扩充到全部 11 类（classes.json 已定义：敌我英雄/兵线/塔/水晶/野怪/hook_aim/skill_effect）；用现有 annotate.py + scrcpy-mask 半自动补标（先用你模型预测做预标注再人工修正，能省 70% 时间）；YOLO 训练 → TensorRT 导出。
2. **小地图模块**：固定 ROI 提取 → HSV 圆点聚类（蓝/红/黄/塔点）→ 单应变换 → 全局地图坐标 + 视野掩码（自己视野半径）。产出：敌方 5 人位置（含视野外）、兵线位置、塔状态。
3. **UI 数值模块**：血条（绿/红条像素比例 → HP%）、技能冷却（暗色遮罩比例或 OCR 秒数）、金币、等级、装备栏（模板匹配图标）、大招就绪状态。
4. **状态融合器**：主战场框（像素坐标）+ 小地图全局坐标 + UI 数值 + 追踪 ID/速度 → 统一 GameState；输出 15 FPS 的状态流。
5. **校准工具升级**：半自动标定（小地图四点、血条 ROI、按钮 ROI），支持分辨率变化自适应。

**验收**：对一段新录像，状态提取与人工核对：敌方位置命中率 ≥90%（小地图），血条误差 ≤5%，追踪 ID 30 秒不漂移；检测 FPS ≥15。

### M2 动作系统（1-2 周）—— 手指级操控
**交付物**
- 动作原语库（连续化）：`move(θ, r)` 连续摇杆（不再是 8 向离散）、`skill_cast(id, mode, x, y)`（点按/拖动瞄准/取消）、`attack(优先级)`、`buy_item`、`level_skill`、`recall`、`summoner`、`active_item`、`camera`。
- 执行器：mumu-python-api 常驻连接（替代每次 subprocess adb）；触摸事件合成与轨迹平滑（贝塞尔）；**动作时间戳流**写入存档（与录像对齐的关键）。
- 抖动与频率控制（防检测 + 拟人化，见 §7 风险）。
- 组合技引擎：`sequence([...])` 支持"2技能→1技能→大招"连招编排与取消条件。

**验收**：钟馗在训练营完成：连续 8 方向走位、拖动 2 技能瞄准指定目标点命中、连招序列一键执行；动作延迟 ≤30ms；录像回放显示操控与真人轨迹分布相似。

### M3 数据工厂（3-4 周）—— 比赛录像 → 训练集
**交付物**
1. **录像管线**：源 = 比赛录像为主 + 少量自录。下载/录制 → 切帧 → 状态提取（复用 M1）→ 存档。
2. **动作反推 v2（多通道合并）**：
   - 通道 A 摇杆箭头：白色箭头 HSV/模板（已有）→ 移动方向（连续角）。
   - 通道 B 按钮高亮：技能/攻击/回城键按下瞬间的亮度/贴图变化（已有雏形）→ 技能释放事件。
   - 通道 C 技能特效与位移：`skill_effect` 检测 + 单位血量突变 + 位移突变（闪现/钩子）→ 反推"哪个技能在哪个目标上被释放"。
   - 通道 D 指示器：技能拖动时出现的瞄准线/圈（补充 B 的"拖瞄"判定）。
   - **交叉验证**：多通道一致才给高置信标签；冲突样本进人工队列。
3. **人工校正标注器**：半自动"反推结果 + 帧预览 + 一键修正"，你确认少量手动标注可行——目标是 1000 局录像出 ~5-10 万高质量 (state, action) 样本。
4. **对齐标定**：录像帧时间 vs 动作时间偏移估计（互相关/人工锚点）；输出标准训练集格式。

**验收**：100 局录像 → 动作反推人工抽检准确率 ≥90%（移动方向、技能事件）；10 万级样本库建立；样本分布统计（各类动作占比健康，无长尾空洞）。

### M4 模仿学习 Baseline（4-6 周）—— 先达到"会玩"
**交付物**
- **策略网络 v1**：输入 = 最近 4 帧 GameState（结构化编码：单位列表嵌入 + 小地图栅格 CNN 特征 + UI 数值 + 上一步动作），输出 = 动作分布（移动连续角 + 技能/攻击离散 + 目标点回归），小 Transformer + 行为克隆损失。
- 训练管线：样本权重、序列采样、验证集（按录像切分，防泄漏）。
- 在线部署：Agent v2 = 感知(M1) + 策略(v1) + 动作(M2)，替换手写规则。
- **评估**：人机 1v1/5v5（难度 1→5）胜率；真人匹配（低段位小号）胜率；与 M0 规则 Agent 对比录像。

**验收**：人机难度 4 稳定胜率 ≥80%；真人黄金-铂金段位胜率 ≥60%（这是"会玩且不送"的标志）；决策延迟 ≤50ms。

### M5 强化学习自博弈（8-12 周+，两档）—— 超越人类
**交付物**
1. **环境封装 GameEnv**：观测 = GameState 流；动作 = M2 原语；奖励 = 稀疏（胜负）+ 稠密 shaping（击杀/助攻/推塔/补兵经济/视野分/死亡惩罚/时间惩罚），带折扣。
2. **PPO + 课程学习**：从 1v1 墨家机关道（双开 MuMu 即可跑）开始：BC 初始化 → 自博弈 → 战胜 M4 策略 → 逐步加强对手（含规则强手）。
   - **本机档**：1v1 闭环 + 5v5 对固定 bot 池优化（4-5 开）。
   - **云 GPU 档**（冲刺超职业）：5v5 双开 self-play + League 训练（多策略池），租 1-2 台 A100/H800 数周。
3. **reward 消融**：分模块验证 shaping 项收益（先金币/死亡，后视野/塔）。
4. **鲁棒化**：观测噪声注入（检测抖动）、动作随机化，防止过拟合到自家感知误差。

**验收（本机档）**：1v1 胜率 >95% vs M4 策略；5v5 真人荣耀王者段位局（小号）胜率 ≥55%。
**验收（云 GPU 档，超职业目标）**：对 KPL 级真人选手（邀请测试或高段位账号）胜率 >50%，录像回放价值评分显著高于职业选手均值。

### M6 评测体系与持续迭代（贯穿 + 持续）
- 评测矩阵脚本 `eval_matrix.py`：固定 bot 池、真人挑战赛、录像回放对比（价值函数评分）、段位爬升速度、回归测试（防感知改动导致水平回退）。
- 版本管理：模型/数据/配置三线版本化，每次改动跑评测矩阵，记录 ELOrating 曲线（用 AI 对 AI 快速排序近似 ELO）。
- 新版本 UI / 英雄改版 → 标定自适应 + 数据增量更新流程。

## 4. 模块详细设计

### 4.1 感知层技术细节
- **主战场检测**：输入 960×540（或按窗口比缩放），YOLO11s-TRT FP16；对检测框做 NMS 后接 ByteTrack；输出归一化像素坐标 + ID + 速度（帧差/滤波）。8GB 显存注意 batch=1 推理 + 显存池复用。
- **小地图**：ROI 由校准点 `minimap_center` 定（当前 1280×720 下约 (110, 93) 中心，半径 ~105px）；HSV 阈值分阵营圆点（蓝 #3b6cf6 / 红 #e05b4a / 野怪黄）→ 连通域聚类 → 质心；用"已知两点（如自家水晶与敌方水晶在小地图的位置）"做相似变换标定；输出全局坐标（0-1 归一化，蓝方左下原点）。
- **视野掩码**：以自身全局坐标为中心、半径 = 英雄视野（标定值，或从"敌方点消失距离"自学习）做圆形掩码，供决策层区分"确定/不确定"信息。
- **UI 数值**：固定 ROI 模板 + 数字 OCR（PaddleOCR 已装，小字用 2-3 倍放大）；血条用像素比例（绿/红像素计数），技能冷却用"按钮遮罩面积比例"，冷却数字 OCR 辅助。
- **置信度校准**：对检测置信度做 temperature scaling（用标注数据），决策层只信任 calibrated 概率。

### 4.2 GameState schema（定版草案）
```json
{
  "t": 123.456,                 // 全局时间戳(秒)
  "camera": {"hero_id": 3, "map_x": 0.42, "map_y": 0.35, "screen_center_map": [..]},
  "units": [                    // 所有视野内单位（含自己）
    {"id": 3, "cls": "ally_hero", "camp": "blue", "screen": [x,y,w,h],
     "map": [0.42, 0.35], "hp": 0.83, "vx": 0.002, "vy": -0.001,
     "dead": false, "t_last_seen": 123.456, "skills": [0,1,0]}
  ],
  "minimap": {                  // 视野外信息（不确定性显式化）
    "enemy_heroes": [[0.71, 0.62], ...], "enemy_minions": [...],
    "turrets": [{"map":[..], "camp":"red", "alive":true}], "monsters": [...]
  },
  "ui": {"gold": 3420, "level": 7, "xp": 0.62, "skill_cd": [0.0, 2.3, 0.0],
         "ult_ready": true, "items": ["boots","rod"], "summoner_cd": 0.0,
         "attack_mode": "free", "recall_cd": 0.0, "kills": 3, "deaths": 1, "assists": 2},
  "self": {"map": [0.42,0.35], "hp": 0.83, "mp": 0.55, "moving": false,
           "skill_indicator": null | {"skill": 2, "dir": [0.9, -0.3]}},
  "last_action": {"type": "move", "theta": 2.1, "r": 0.9, "t": 123.42},
  "frame_meta": {"src": "replay|live", "match_clock": 421, "video": "KPL_xxx.mp4", "frame": 10234}
```

### 4.3 决策层
- **策略网络输入编码**：单位列表 → 类别嵌入 + 相对屏幕/地图坐标 + 血量/速度 → 序列 Transformer（自注意力捕捉"谁威胁谁"）；小地图 → 小 CNN（40×40 栅格，通道 = 阵营单位/塔/兵/野怪/视野掩码）；UI 数值 → MLP 头；三者拼接 → 动作头（连续 θ/r + 分类技能/攻击/其他 + 目标点回归，用 GMM 或 discretized 输出）。
- **分层执行**：宏观目标选择器（决策频率 2-4 Hz，选目标：清线/支援/推塔/回城）→ 微观操作器（10-15 Hz，执行走位/技能）。分层降低训练难度，也便于人工干预与调试。
- **连招引擎**：规则化"钩子→1技能→大招"触发条件（2 技能命中判定），作为策略网络的先验动作模板；RL 阶段可被学习覆盖。

### 4.4 训练
- **BC 阶段**：数据 = M3 样本库；loss = 交叉熵(离散动作) + MSE(连续移动/目标点)；验证按录像分组；评估用 M4 验收指标。
- **RL 阶段**（PPO）：并行采样 = MuMu 双开/四开 + 本机多进程；奖励按 §3-M5；价值函数输入同策略；训练稳定技巧：GAE、clip、熵正则、reward normalization、课程对手。
- **League（云档）**：维护策略池，定期"主策略 vs 池内对手 + 池内互相打"，防单峰退化——AlphaStar/绝悟同款思想。

### 4.5 评测
- 自动化：固定 10 个 bot 组合池（人机难度 5 配置 × 不同英雄）跑 20 局算胜率；真人挑战赛（小号匹配，统计 50 局）。
- 录像回放对比：同局录像 → 提取双方状态 → 用训练好的价值函数（critic）对每帧打分 → 对比 AI 局 vs 职业选手局的价值曲线与决策差异热力图。
- ELO 快排：AI 各版本互相打，快速排序估 ELO，避免真人评测的方差。

## 6. 延迟预算（全链路目标 ≤160ms）

| 环节 | 现状 | 目标 | 手段 |
|---|---|---|---|
| 采集 | 5-15ms (mss) | ≤20ms | 窗口直抓；对比 mumu-python-api 截图 |
| 检测 | 30-80ms (yolov8n CPU 动态图) | ≤35ms | YOLO11s + TensorRT FP16 + 960×540 |
| 小地图+UI | 未做 | ≤10ms | 小 ROI + 轻量算法 |
| 决策 | 手写规则 <5ms | ≤40ms | 策略网络 TensorRT/半精度，2-4Hz 宏观 + 10-15Hz 微观 |
| 动作下发 | 30-100ms (每次起 adb 子进程) | ≤20ms | mumu-python-api 常驻连接 |
| **端到端** | **150-250ms（且抖动大）** | **≤160ms** | 流水线并行 + 双缓冲 + 时间戳 |

> 职业选手反应时间约 200-300ms，但"超过职业"靠的不是更快，而是**更准的全局信息（小地图+追踪预判）与更优决策**；延迟预算的意义是把"反应"让给"决策"。

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 录像动作反推不准（无原始输入） | 高 | 多通道交叉验证 + 人工校正标注器；只保留高置信样本；自录数据（有真实输入）做校准锚点 |
| 感知误差传导（检测漏检→决策错误） | 高 | 小地图兜底（视野外目标不依赖主镜头）；置信度校准；RL 时注入观测噪声 |
| 算力不足（8GB 本机） | 中 | 小模型 + ROI 分治；RL 先 1v1；超职业阶段按需租云 GPU（计划已分档） |
| 封号/违规风险（自动化对局违反 ToS） | 中 | 仅用于研究账号；操作拟人化（抖动/随机化/频率限制）；不碰高价值账号；控制对局时长与频率；了解并接受风险后再跑真人局 |
| 游戏版本更新导致 UI/英雄改动 | 中 | 标定文件外置 + 自适应检测（ROI 漂移校正）；增量数据更新流程 |
| 自博弈陷入单一策略（如只会勾人） | 中 | League 策略池 + 课程对手 + reward 多样性 |
| 5v5 双开自博弈不稳定（掉线/卡死） | 中 | 对局守卫脚本（断线重连、异常重启、掉线自动重开） |
